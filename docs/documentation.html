Battle Editor — Function & Module Reference

This is a reference for everyone working on the Battle Editor codebase — a React + TypeScript app for visually building "hex-grid battle" HTML5 playable ads, previewing them live, and exporting them for Facebook, Google Ads, Unity/AppLovin and Mintegral.

It documents every exported function, store action, component and the embedded playable runtime that gets generated into the final ad file.

Architecture overview

The app is a single-page editor built around one shared state object, BattleConfig (the entire battle definition: units, heroes, spells, scenario, popups, assets, audio, layout). Every panel in the left navigation reads and writes pieces of this config through a single Zustand store. A live preview and an export dialog both turn the current config into a self-contained, runnable HTML5 playable via one function: generateHTML().

Data flow

Config Panels (UnitsPanel, SpellsPanel, …) → useBattleStore (Zustand) → BattleConfig → generateHTML(config, network) → LivePreview (iframe) / ExportDialog (download)

Assets (images/audio) are uploaded as base64 data URIs (assetEncoder.encodeFile) and stored directly inside BattleConfig, so the exported HTML is fully self-contained with no external file references (except Mintegral, which is split into index.html + main.js).

Playable generator — src/utils/htmlGenerator.ts

src/utils/htmlGenerator.ts

generateHTML(config: BattleConfig, network: NetworkTarget): string

The single most important function in the project. Takes the full BattleConfig and a target network, and returns a complete, self-contained HTML document — markup, CSS, embedded assets (as data URIs) and a JavaScript game engine — that runs the hex-grid battle as a playable ad.

Used by both LivePreview (rendered live in an iframe) and ExportDialog (downloaded per network).

  • Strips audio entirely when network === 'facebook' (hasAudio flag) to meet its strict size limit.
  • Inlines all unit/spell/UI/background/audio assets as data URIs so the file needs no external resources.
  • Serializes scenario data (enemies, retaliations, fail-condition hints, alternating turn order & reactions, winning sequence) into JS constants consumed by the embedded engine.
  • For Mintegral exports, ExportDialog later splits the returned HTML at the inline <script> tag into index.html + main.js.

Modal that, for each of the 4 supported networks, generates the playable HTML via generateHTML, estimates its size with estimateSize, and shows whether it's within that network's size limit (Facebook 2 MB; Google Ads, Unity/AppLovin and Mintegral 5 MB).
